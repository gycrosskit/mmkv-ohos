## Core 与五种消费入口

本 fork 的 KMP 项目是 `KMP/:mmkv`，发布 artifact 为 `mmkv-kmp`，包为 `com.tencent.mmkv.kmp`。Android actual 委托官方 `com.tencent:mmkv:2.4.2` AAR；iOS/OHOS 的 nativeMain actual 通过 [C bridge](../Core/cbridge/MMKVBridge.cpp) 复用 MMKV Core。没有 CMP/Kuikly UI 模块。仓库中的上游 Flutter、Python、原生 Android/iOS 与 OpenHarmony 工程不是本 KMP artifact 的额外 public API。

| 五种入口 | 实际实现 | 宿主职责 |
| --- | --- | --- |
| CMP Android | KMP Android actual + 官方 JNI | Application 中 `MMKV.initialize(context)`，AndroidX、minSdk23 |
| CMP iOS | KMP Native actual + Darwin initialize | `MMKV.initialize()`，默认 Documents/mmkv；最低部署 iOS13 |
| Kuikly Android | 同 CMP Android Core | 由原生宿主初始化，不随重组重复初始化 |
| Kuikly iOS | 同 CMP iOS Core | 由原生宿主持有与关闭；避免再链接含 Core 的 MMKV Pod/SwiftPM |
| Kuikly OHOS | KMP Native actual + OHOS initialize | `MMKV.initialize(rootDir)`，私有可写目录、最终 .so 打包；ArkTS 需宿主 FFI |

KMP OHOS 不要求另装 `@tencent/mmkv` ohpm 包；这不等于提供 ArkTS 桥。维护分支为本 fork `main`，KMP 适配构建见 [KMP/settings](../KMP/settings.gradle.kts)；不能用上游仓库 main 推断本 fork 支持范围。

## 公开 API / 功能组

| 功能组 / 源码 | 公开能力 | 三端实际差异 |
| --- | --- | --- |
| [MMKV](../KMP/mmkv/src/commonMain/kotlin/com/tencent/mmkv/kmp/MMKV.kt) 编解码 | Bool、Int、Long、Float、Double、String、Bytes 的 encode/decode 与默认值/TTL overload；containsKey、allKeys、count、valueSize、remove 等 | Android JNI；iOS/OHOS 同 Native C bridge。String 采用 UTF-8 bytes 路径并兼容旧字符串解码 |
| [MMKVConfig](../KMP/mmkv/src/commonMain/kotlin/com/tencent/mmkv/kmp/MMKVConfig.kt) / [MMKVNameSpace](../KMP/mmkv/src/commonMain/kotlin/com/tencent/mmkv/kmp/MMKVNameSpace.kt) | defaultMMKV、mmkvWithID、namespace、mode、cryptKey、rootPath、expectedCapacity、TTL 配置 | 三端模型共用；平台 initialize 入口不同 |
| MMKV 文件/加密/恢复 | sync/async、trim、clearMemoryCache、close、reKey/checkReSetCryptKey、importFrom、backup/restore/removeStorage | Native 由 Core 实现；Android 使用官方 AAR，不声明每个底层行为已经跨端实测 |
| MMKV TTL/锁/回调 | enableAutoKeyExpire/disableAutoKeyExpire、lock/unlock/tryLock、registerHandler 等 | Native 四个 C ABI 回调吞住宿主异常；恢复异常默认 OnErrorDiscard；Android 不改变上游 handler 策略 |

**本 KMP public contract 没有 StringSet encode/decode**。上游 Android/Objective-C/ArkTS 的其他类型或工具不能直接当作 `com.tencent.mmkv.kmp` 已发布能力。精确 overload 以公共声明为准：[Android actual](../KMP/mmkv/src/androidMain/kotlin/com/tencent/mmkv/kmp/MMKV.android.kt)、[Native actual](../KMP/mmkv/src/nativeMain/kotlin/com/tencent/mmkv/kmp/MMKV.native.kt)。

## 差异分类与生命周期

- **组件范围/不提供的入口**：本 KMP public contract 本来不包含 StringSet；基础设施 artifact 不提供 UI 或现成 ArkTS 入口。这些不是本轮待补齐实现，也不承诺拥有上游其他平台的所有 API。
- **OS/SDK 限制**：普通 Kotlin2.2.21 不含 ohosArm64，使用 `2.2.21-1.0.0` 及对应 SDK；iOS Native 链接需 macOS/Xcode。同 iOS 二进制叠加另一个 MMKV Core 可能重复符号。
- **宿主职责**：初始化私有目录、备份策略、加密 key 管理、串行关闭、跨进程模式配置。close 销毁原生实例，所有指向同实例的别名失效；必须先结束读写再关闭并丢弃旧引用，不能把单方法锁当 close 并发安全保证。
- **本轮修改**：defaultMMKV()/mmkvWithID(id) 复用既有 config overload，删除重复默认 C 配置；Native C callback 边界隔离异常，保留正常 recovery 返回值。没有修改底层 Core 算法或新发布版本。
- **未验收**：真实 OHOS KMP 宿主持久化/重启、多进程锁压力、实际损坏文件 CRC 恢复、ArkTS 共存及真机；不把 callback 返回值 fixture 当成损坏文件恢复成功。

**时点**：前轮代码复核运行 Simulator 11项及 Android/OHOS 编译；本轮最终核对仅加固 Native callback 测试并定向重跑，生产源码不变。

| [NativeHandlerBoundaryTest](../KMP/mmkv/src/nativeTest/kotlin/com/tencent/mmkv/kmp/NativeHandlerBoundaryTest.kt) | **本轮新跑** `KMP/:mmkv:iosSimulatorArm64Test --tests com.tencent.mmkv.kmp.NativeHandlerBoundaryTest`，1项；调用生产 staticCFunction 指针，确认7个抛错宿主回调实际到达、异常隔离与 recovery 0/1 返回 | C ABI fixture；不是实际损坏文件触发、跨进程通知或 Android 上游 handler 验收 |
